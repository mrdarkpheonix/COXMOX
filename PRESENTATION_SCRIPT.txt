THE COXMOX - SHORT PRESENTATION SCRIPT
======================================
Approximate duration: 1-2 minutes

[Opening - show the world map]
"This is The Coxmox: an accessible way to explore changing conditions on
Earth through a map, spoken information, and sound. It is an educational
prototype created for the Earth Information Jukebox challenge."

[Show the mode switch, event list, and a selected marker]
"The app loads open natural-event reports from NASA's EONET service and
plots events on a world map. You can filter by event category, then choose
between two experiences. Instrumental mode gives each event type a distinct
musical instrument and phrase, such as marimba for wildfires, piano for
floods, and bells for sea ice. Vocal mode uses a speaking agent to describe
the selected event. If live event data is unavailable, the app falls back
to clearly identified sample data."

[Show controls]
"The controls are designed to work with a keyboard and assistive
technology. Supported browsers can accept voice commands. The app asks for
location permission at startup, but location is optional. When permission is
granted, a nearby event opens a warning dialog, plays its matching instrument
for 20 seconds, then speaks an informational summary. If permission is denied,
you can click the map or enter latitude/longitude coordinates to set a custom point;
choose Use device location to switch back. Browser settings may block
automatic audio; the dialog offers retry and speak-now controls."

[Show climate context and status]
"A separate panel shows the latest available NOAA ONI reading as broad
climate context. Eco mode reduces refresh frequency and shortens the
sonification."

[Closing]
"The sound is an artistic interpretation, not a scientific instrument.
The app is not an official NASA product, warning service, or forecast.
Its simple storm trend estimate can be wrong, so users should always rely
on local authorities for safety decisions. The goal is to make Earth data
more approachable through multiple senses while being clear about limits."

DEMO CHECKLIST
--------------
* Start the app before presenting; confirm the live-data or demo-data status.
* Have one event ready to select and play.
* Demonstrate one filter and one keyboard shortcut (for example H or N).
* Grant location only if the presenter has chosen to share it; browser
  permission is requested automatically at startup.
* Do not describe the storm trend estimate as a forecast or safety warning.
